# PlayGif 1.0.2 — release note

**Tag:** `1.0.2`
**Title:** `PlayGif 1.0.2 — localized descriptions, MP4 conversion, and a fix attempt for the restart bug`
**Asset:** `PlayGif-1_0_2.pext`

---

## GitHub release body

Fixes the language bug reported in #1, adds MP4 conversion for cached media, and takes a run at the restart bug in #2.

### Fixed
- **Store descriptions are fetched in your language** ([#1](https://github.com/aHuddini/PlayGif/issues/1)). Steam's API returns English unless it's told otherwise, so PlayGif was replacing localized descriptions with English text. It now uses your Playnite language for both Steam and GOG, and caches each language separately — so switching language re-fetches instead of reusing the English copy.

  English users see no change: the parameter is omitted entirely, and existing caches stay valid.

### Added
- **Convert cached media to MP4** (Settings → General → Cache). Re-encodes your cached GIFs and other animations with FFmpeg. A GIF stores every frame as a full picture, so the saving is large — a 116 MB test library came out at roughly 8 MB — and MP4 plays on your GPU where GIF does not.
- **Repair description links**, next to it. Points descriptions at the converted files, and clears links whose media is no longer on disk. Runs automatically after a conversion.

### Fix attempts
- **Descriptions reverting to plain text after restarting Playnite** ([#2](https://github.com/aHuddini/PlayGif/issues/2)). PlayGif retried attaching to the description panel a fixed number of times, then gave up. Playnite fires several game-selection events during startup, so in the reporter's log all retries were spent within 27 milliseconds — before Grid view's description panel had been built. Across that log, 18 of 48 sessions never attached.

  The retry limit is gone, and PlayGif now attaches the moment the panel appears rather than waiting for another game selection.

  **This is marked a fix attempt, not a fix.** It depends on startup timing that varies by machine, theme, and library size, and cannot be reproduced reliably outside a real session. If descriptions still revert after a restart, please [open an issue](https://github.com/aHuddini/PlayGif/issues) with `extension.log` — Settings → PlayGif → Theme Support → Open log folder.

### Changed
- Quieter logging while waiting for the description panel during startup.

### Known issues
Theme compatibility remains the rough edge. Playnite has no official support for animated descriptions, so PlayGif injects its renderer into whatever description panel your theme builds — themes vary, and other extensions modify the same panel. Some themes may not work at all. The **Known Issues** tab in settings covers this, and the **Theme Support** tab generates a layout report for bug reports.

### Install
Download `PlayGif-1_0_2.pext` and open it with Playnite, or Add-ons → Extensions → Add extension.

**Upgrading?** Settings carry over. If you use Playnite in a language other than English, descriptions re-fetch once in your language.

**Full changelog:** https://github.com/aHuddini/PlayGif/blob/main/CHANGELOG.md

## Short version (Discord / Reddit comment)

**PlayGif 1.0.2** is out — two reported bugs.

**Fixed:** descriptions were always fetched from Steam in English, overwriting localized text. Now uses your Playnite language for Steam and GOG, cached per language.

**New:** a **Convert cached media to MP4** action in settings. GIFs store every frame as a full picture, so converting them is a big win — my 116 MB of cached GIFs came out around 8 MB, and MP4 decodes on the GPU. Needs FFmpeg.

**Fix attempt:** descriptions reverting to plain text after restarting Playnite. PlayGif gave up attaching to the description panel too early — the retries were all spent within milliseconds of startup, before Playnite had built the panel. That limit is gone. Calling it an attempt rather than a fix because it depends on startup timing I can't reproduce reliably; if it still happens, send a log.

## Cutting the release

```bash
cd /c/Projects/PlayGif

# 1. merge to main
git checkout main && git merge --ff-only dev && git push origin main

# 2. rebuild so the asset matches main
dotnet clean -c Release && dotnet build -c Release
powershell -ExecutionPolicy Bypass -File scripts/package_extension.ps1

# 3. name the asset to match installer.yaml's PackageUrl
cp "pext/PlayGif.2e196d25-24d1-4db3-b732-9766c994a496_1_0_2.pext" pext/PlayGif-1_0_2.pext

# 4. cut the release
sed -n '/^## GitHub release body$/,/^---$/p' docs/release_notes/1.0.2.md \
  | sed '1d;$d' > /tmp/pg-notes.md

gh release create 1.0.2 pext/PlayGif-1_0_2.pext \
  --target main \
  --title "PlayGif 1.0.2 — localized descriptions, MP4 conversion, and a fix attempt for the restart bug" \
  --notes-file /tmp/pg-notes.md
```

## Notes

- Issue #1 was verified directly against the live Steam API — `l=koreana` returns Hangul, and the `<video>` markup survives. 24 unit tests cover the locale mapping.
- Issue #2 **could not be verified here**. It needs a real Playnite startup in Grid view. Worth testing before release, and worth leaving the issue open until a reporter confirms.
- `arabic` and `hebrew` are valid Steam codes but return English for every app tested — Steam translates game listings into them but not store descriptions. Harmless to keep in the table.
